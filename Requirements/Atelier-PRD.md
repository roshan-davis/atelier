## Overview

Atelier (working name) is a native macOS photo catalog and non-destructive RAW editor for personal use, with first-class hooks for external editors and local AI models. It replaces a Lightroom subscription for one photographer and artist, and treats AI models as pluggable processing steps rather than a fixed feature set.

**Problem.** Lightroom locks the catalog, the develop pipeline and AI features into one subscription and one cloud. Local AI image models (Qwen-Image-Edit, FLUX.2 Klein, upscalers, segmenters) now match or beat built-in AI tools, but there is no catalog that can route a photo through them and keep the result versioned next to the original.

**Goals**

1. Catalog 100k+ images across local drives and the megham NAS, either in place or copied into a managed library.
2. Non-destructive develop module at Lightroom Classic parity for everyday work: RAW decode, tone, color, HSL, curves, local masks, presets.
3. Round-trip any photo to any external editor (Photoshop, Affinity, Pixelmator Pro, GIMP, Krita) and re-import the result as a stacked version.
4. Run AI edits through pluggable local backends (ComfyUI, Core ML, MLX) with a model registry that tracks license and allowed use.
5. Export web-ready images for roshandavis.com and social posts with presets for size, color space, watermark and metadata.

**Non-goals**

- Cloud sync, multi-user catalogs or mobile apps in v1.
- Training or fine-tuning models inside the app.
- Video editing (video files are cataloged and previewed only).
- Windows or Linux support.

## Target user and use cases

One user: a photographer and watercolor artist running an art business, editing on an Apple Silicon Mac, with originals split between local drives and a NAS. Every use case below must work fully offline except NAS access.

## User experience principles

Every feature follows these rules. A feature is not done until it meets them.

1. **Start with the task, not a system dialog.** A command opens Atelier's own dialog first; file pickers are a step inside it, never the entry point.
2. **Show what will happen before it happens.** Dialogs preview the outcome (for example "Import 128 photos" on the button) and disable the action until it can succeed.
3. **Drag and drop everywhere it makes sense.** Folders and photos dropped on the window or a dialog do the obvious thing.
4. **Long work runs in the background, visibly.** Imports, previews, exports and AI jobs show progress, can be cancelled, and never block browsing or editing.
5. **Results appear when they are ready.** An import shows its progress (count, amount copied, speed, time left, current file) in its own dialog, with Cancel and Run in Background, instead of filling the grid one photo at a time; the new import entry is selected once every file is in. (Rosh, Oct 30, 2026: rendering while copying was slow and distracting.) Other long work (previews, exports, AI) fills in as it arrives.
6. **Nothing destructive without a clear confirmation.** Deleting a list explains what is kept ("the photos stay in your catalog and on disk"). Originals are never modified.
7. **Errors name the file and the reason**, and the rest of the batch continues. Problems are listed on request instead of interrupting with alerts.
8. **Keyboard first for repeated work.** Culling, rating, flagging, labels and view switching all have single-key shortcuts; every command is in a menu. Develop works from the keyboard the Mac way (see Keyboard focus in Develop): a focused slider takes the arrow keys, Tab moves between controls, ⌃Tab between areas, and every command key can be changed in Settings > Keyboard. Focus shows as a quiet mark (a thin accent bar and faint tint, faded in, still with Reduce Motion), not the system's thick ring. (Rosh, Nov 9, 2026.)
9. **Sensible defaults, remembered choices.** Names default to the folder or event, the last import mode and library folder are remembered, and Atelier reopens on the view, photo and filter you left (see Restore last session).
10. **Switching modes keeps your place.** Opening a tool (Crop, Masking, AI, Guided Upright, the white balance picker, Loupe and Develop) and coming back keeps the zoom and the spot you were zoomed in on; a crop moves the spot with the photo. This is one shared view state that every mode reads and writes, not something each tool saves for itself. (Rosh, Oct 29, 2026.)
11. **The cursor always says what a click or drag will do.** Resize arrows on frame edges, corners and dividers (diagonal at crop corners), a hand where a drag moves something (the zoomed photo, a pin, a handle, the Navigator rectangle) that closes while dragging, a curved arrow where a drag rotates, a crosshair where a drag draws or paints, an eyedropper for every color picker, a pointing hand where a click selects, and the arrow over a photo with nothing to pan: no magnifier, since zoom is a double-click and a magnifier says a single click zooms (Rosh, Oct 30, 2026, AT-020; the hand shows only when part of the photo is out of view). A drag keeps its cursor until the mouse goes up, even off the handle, and a tool that closes puts the arrow back. One shared mechanism does this (`Cursors.swift`: views name a `CursorShape` for a spot, worked out with the same hit test their drag uses); no view sets an `NSCursor` itself, so a new tool gets correct cursors by naming its shapes. (Rosh, Oct 29, 2026.)
12. **Deleting sounds and looks like macOS.** Moving photos to the Trash plays Finder's Trash sound; removing anything from Atelier (a mask or mask part, preset or preset group, guide, snapshot, virtual copy, collection, import entry, or photos taken out of the catalog) plays the Dock's poof sound. Both show a small puff of smoke at the pointer (the window's middle for a delete from the keyboard). One function (`DeleteFeedback.play`) does it for every delete. Settings > General > Feedback turns it off; the sound follows System Settings > Sound > "Play user interface sound effects" and the puff is skipped with Reduce Motion. (Rosh, Oct 29, 2026. Rosh remembered it from Lightroom; the poof and both sounds are macOS's own, from the Dock and Finder.)
13. **Every tool looks and works the same way, wherever its idea came from.** Whether a feature comes from Lightroom, another app or our own idea, it uses the same controls, gestures and wording as the rest, so learning one panel teaches them all. Each pattern is built once and reused; a tool with its own copy, or missing a pattern the others have, is a bug. Develop sections in both columns share one header, the VS Code–style band Rosh chose for the left column (uppercase title on a shaded band, Oct 29, 2026): click to open or close, a dot when the panel has edits, a reset arrow, an on/off switch on every panel but Basic (see Develop), and a right-click menu with Solo Mode, Expand All and Collapse All. Every slider, group heading and color picker works the same way too (see Sliders, group headings and color pickers under Develop). (Rosh, Oct 29, 2026, after seeing only Color Grading had a switch.)
14. **Plain language.** Labels describe what happens to the user's photos ("Leave files where they are", "Copy into my library folder"), not internal terms.
- **Long names stay on one line.** File names, folder paths, lens and camera names in panels and lists are one line, cut with an ellipsis (in the middle for names and paths, so both ends stay readable), with the full text on hover. They never wrap or widen a panel. (Rosh, Oct 30, 2026.)

### Import flow

15. File > Import Photos (Shift-Cmd-I), the toolbar button, or dropping folders or photos on the window opens the Import dialog.
16. **Layout (redesigned Oct 30, 2026, after Rosh found the stacked form "like a busy backend engineer made it"):** laid out like Lightroom's import window, at one fixed size (1100 × 760) for every step and every choice, so it never resizes (Rosh: "jumpy dialogs are painful").
   - **Header:** a tinted band with an icon that follows the step (photos, a stack for Cull, the import arrow), the title, a line saying what this step is for, and the steps on the right as large numbered circles (a check once done) with their names underneath, joined by lines: **Choose Photos › Import**, or **Choose Photos › Cull › Import** with culling on.
   - **Middle (Choose Photos):** the chosen folders as chips along the top (name, photo count, ⊗ to take one out, "Add…"), and below them thumbnails of every photo found (a RAW and its JPEG once), from their embedded previews. With nothing chosen yet: a large drop area with "Choose Folders or Photos…". Folders and photos can be dropped anywhere on the dialog.
   - **Right:** collapsible panels with the same header bands as Develop, remembered open or closed: **Import Into** (new import or an existing one, and the new one's name), **File Handling** (leave files where they are, or copy into the library folder, with Change…), **Apply During Import** (develop preset, keywords), **Culling** (Cull before importing).
   - **Name:** the new import's name starts as the first folder's name, as real text in the field, not a placeholder, so typing adds to it; it follows the chosen folders until the user edits it (Rosh, Oct 30, 2026).
   - **Cull step:** while photos are checked, the list wraps them to the width of its pane (nothing is cut off), the large preview already shows the focused photo, and Keep/Drop appear once the groups are ready. When the groups appear, the first photo of the first group is focused, so the arrow keys start from the top.
   - **Footer** (the same bar on every step): a summary on the left ("412 photos · 18.4 GB · copied into Atelier Library · into “Beach”"), Cancel and the main button on the right.
17. The Import button reads "Import N Photos" and is disabled until at least one photo is found.
18. **One dialog from start to finish (Oct 30, 2026).** After Import the dialog stays open and shows the import's progress in place of the settings: a card with "137 of 412 photos copied" (or "added" when files stay where they are) in large figures, a progress bar, the file being copied, and three figures below it: Copied ("6.1 GB of 18.4 GB"), Speed ("180 MB/s", measured over the last few seconds so files copied ahead during culling don't inflate it) and Time left ("About 1 minute", from that speed). **Cancel Import** (Esc) stops it; photos already copied stay in the catalog and a half-copied file is removed. **Run in Background** closes the dialog and leaves the progress, with Cancel, in the status bar. The dialog closes by itself when every file is in, and the import entry is then selected.
   - With **Cull before importing** on, Continue to Cull replaces the settings with the Cull view in the same dialog (no return to the main window between steps); Back returns to the settings as they were; Import moves to the progress step. The Cull view's list and large photo are side by side with a draggable divider (the list's width is remembered); the list is always laid out at exactly its pane's width, so group rows and the analysis status wrap or truncate instead of being cut off at either side.
   - **Speed:** files are copied a few at a time; each file is read once, hashed as it is copied, then the copy is verified against that hash. On the same APFS volume the copy is a clone (instant, no extra space). Thumbnails and previews are made only after every file is in, so they don't compete with the copy for the card or drive.
   - **One read of a slow source (Oct 30, 2026, Rosh importing from the NAS at 17 MB/s).** In copy mode every file goes through the staging folder, made ahead while culling or at import time: it is read once, start to end, into a verified local copy, and its metadata (EXIF, embedded XMP) is read from that copy, with the XMP sidecar still taken from beside the original. Reading a raw file's metadata takes many small reads, each a network round trip on the NAS, so it is never done over the network during a copy import.
   - **Copy ahead while culling (Rosh, Oct 30, 2026: "bring the time more down").** Once the Cull step has listed the photos, the files are copied (two at a time, alongside the analysis) into a hidden staging folder in the library root (`.Atelier Staging`), on the same volume as their final dated folder, each verified by hash as it is made. The Cull step's bottom bar shows "Copying to your library while you cull: N of M". On Import the importer takes every finished copy and moves it into place with a rename (no second read of the card), copies the rest itself, and removes the staging folder at the end. A file whose size or modification date changed since is copied again. Back, Cancel or closing the dialog discards the staged copies; a staging folder left by a quit is removed at the next import. When files stay where they are (or the copy would be a clone), each file is hashed ahead instead.
   - **The progress step's wall (Oct 30, 2026).** Behind the progress card, every photo being imported fills the step as a grid: grey and faint until it is cataloged, then in full color with a green check, scrolling by itself to keep the photos being copied in view. After culling it uses the Cull step's thumbnails (no extra reads); otherwise the Choose step's, or the embedded preview read at background priority. The card sits on a translucent material over a vignette so the figures stay readable.
19. When done, the status bar summarizes imported, already-in-catalog and unreadable files, with "Show Problems" listing any failures.

### Culling (decided Oct 26, 2026)

Culling picks the keepers from groups of similar shots (bursts, the same scene taken a few times). It runs before an import or on any import entry later, in the same Cull view.

- **Before importing:** the Import dialog has "Cull before importing". With it on, the button reads "Continue to Culling…" and the dialog's next step is the Cull view on the chosen photos (see Import flow, 18). Only kept photos go into the import entry, with the options chosen in the dialog. The shots not kept are still cataloged (flagged Rejected, outside the entry, under All Photographs and their folder) so they can be re-reviewed; in copy mode they are copied too.
- **On an import entry:** right-click the entry in the sidebar > Cull…, or Library > Cull Import…. When done, kept photos are flagged Picked and the others Rejected (nothing is removed; the Rejected filter hides them and culling again changes it).
- **Grouping:** photos are ordered by capture time; a photo joins the group before it when it was taken close in time (within a minute) and matches it, and also matches the group's first shot a little more loosely, so a slow pan doesn't chain a whole shoot. A Grouping slider goes from Tight to Loose and regroups instantly. Every cull starts at Tight, so different shots are never hidden inside a group unless the user loosens it (Rosh, Oct 30, 2026). Single shots are listed last and kept.
- **Match (updated Oct 27, 2026):** Rosh asked for more than one way of telling similar shots apart. A Match control at the top picks one, and is remembered:
  - **Same Frame:** only shots framed alike from the same spot, where people moved slightly, blinked or changed expression. Measured pixel by pixel: the share of the frame that changed, ignoring exposure differences and a tiny camera shake.
  - **Similar Shots** (default): also the same scene reframed: slightly zoomed or recomposed, people in the background or far away moving, focus on a different subject. Measured by lining the shots up (zooms up to about a quarter, small shifts) and by Vision feature prints. Shots under a second apart (a burst) always join.
  - Each group is labelled Same frame or Similar shots, so a Similar Shots cull still shows which groups are near-identical.
- **RAW+JPEG:** a RAW and the JPEG (or HEIC, TIFF) shot with it are one frame in culling, whatever the RAW+JPEG setting: the RAW is analyzed and shown, marked RAW+JPG, and keeping or dropping it applies to both.
- **Suggested keeper:** in each group Atelier suggests the best photo: the sharpest, and where there are faces, the best face capture quality (eyes open, in focus). It is marked Suggested and starts as the keeper; any photo can be kept or dropped, and a group can keep several.
- **Layout:** groups as rows of thumbnails on the left (kept photos with a check, the rest dimmed), the focused photo large on the right with its sharpness and face quality, counts and the Grouping slider on top, Cancel and Import N Photos (or Done) at the bottom, plus Back in the Import dialog. Scrolling works like Finder and Lightroom's grid: clicking a photo never moves the list, and the arrow keys move it only when the photo they land on is not fully visible, then by the least that shows it (up and down for its row, left and right within a long row). Up and down go to the row above or below at the same place in the row (Rosh, Oct 30, 2026).
- **Keys:** arrows move between photos and groups, P keeps, X drops, Space toggles, Return finishes, Esc cancels. They work as soon as the view opens, with nothing to click first; while the photos are still being analyzed the arrows already move through them in capture order.
- **While it works:** listing and reading the photos shows a centered status ("Reading 412 photos…", with a bar and count); analysis then shows a progress card above the photos with the count and time left.
- **Groups are remembered.** Every photo culled with others shows "◫ n" (the group's size) in the grid. Photo > Show Cull Group (⇧⌘G), or right-click > Show Cull Group (n Shots), opens the Cull view on that one group: the keeper next to every shot it beat, rejected ones included, with the same large preview to re-review and change the keeper. A shot kept on re-review is flagged Picked and joins the group's import entry.
- Analysis runs in the background with progress; for photos already cataloged it reads the files where they are.

### RAW+JPEG pairs (decided Oct 27, 2026)

Cameras set to RAW+JPEG write DSC_0001.NEF and DSC_0001.JPG for one picture. Rosh wants these grouped, with only the RAW shown, and kept separate from culling (which groups different frames).

- **What pairs:** files in the same folder with the same name apart from the extension, where exactly one is a RAW (NEF, CR2, CR3, ARW, RAF, ORF, RW2, DNG and the other RAW formats). The others (JPEG, HEIC, TIFF, PNG) are its siblings.
- **Setting:** Settings > Import > "Show RAW+JPEG pairs as one photo", on by default. On: the grid, filmstrip and counts show only the RAW, with a "RAW+JPG" badge; the inspector lists the sibling files under "Paired With" (renamed from "Shot with" on Oct 30, 2026, which read as if it named the camera). Off: every file is its own photo. Changing it takes effect at once; nothing is re-imported.
- **Cataloging:** every file is still imported and cataloged (with its own hash and metadata), so turning the setting off loses nothing.
- **Edits follow the RAW:** while grouped, ratings, flags, color labels, keywords, collections and import entries set on the RAW are set on its siblings too. Develop settings, Edit In, AI and export use the RAW only, as in Lightroom.
- **Not hidden:** Edit In and AI results and virtual copies, even when their name matches a RAW.

### Virtual copies (decided Oct 26, 2026)

Rosh wants several treatments of one photo (colour and black and white, two crops) without duplicating the file, as in Lightroom.

- **Create:** right-click a photo (grid, loupe or Develop) > Create Virtual Copy, or Photo > Create Virtual Copy (⌘'). With several photos selected, each gets a copy. The new copies are selected.
- **What a copy starts with:** the photo's current develop settings (history starts at one step, "Virtual Copy"), rating, color label, title, caption, keywords, collections and import entries. Flags are not copied.
- **Independent:** each copy has its own develop settings, history, snapshots, rating, flag, label and keywords. Editing a copy never changes the original or other copies.
- **Shown in the stack:** copies sit right after the original in the grid with a "⧉ Copy n" badge; the original shows the stack count. A copy of a copy stacks on the same original. The loupe title and the inspector name the copy.
- **Remove:** right-click > Remove Virtual Copy…, or Photo > Remove Virtual Copy…, after a confirmation. Only catalog data goes; the original and its file are never touched.
- **Files:** a copy shares the original's file. Export names it `name-Copy1.jpg`. XMP sidecars are written for the original only. Re-importing the folder never mistakes a copy for the file. Culling an import entry skips copies.

### Remove and delete photos (decided Oct 28, 2026)

Rosh asked for Remove (from the list) and Delete (from disk) on the right-click menus. As in Lightroom, it is one command with a dialog.

- **Where:** right-click a photo in the grid, Loupe, Develop or the Filmstrip > Remove Photo… ("Remove 3 Photos…" with several selected), Photo > Remove Photo… (Delete), or the Delete key in the library window. It acts on the same photos as the rest of the menu. Delete does nothing while typing, cropping or painting an AI mask, and keeps its own job in Masking and Guided Upright (removing the selected part or guide).
- **Dialog:** names the photo, or says how many photos. **Remove** (the default button) takes them out of the catalog with their develop settings, metadata, collections, import entries and virtual copies; the files stay where they are. **Delete from Disk** also moves the files to the Trash. Cancel or Esc does nothing.
- **RAW+JPEG pairs:** when pairs are shown as one photo, the JPEG (or HEIC, TIFF) goes with its RAW. The dialog then has a checkbox per kind of file, for example "RAW (.NEF) 12 files" and "JPEG (.JPG) 12 files", all checked to start with. Unchecking one keeps those files and their photos; a JPEG whose RAW went shows as a photo of its own.
- **Numbers before acting:** the dialog says how many files Delete from Disk will move to the Trash, how many virtual copies go with the photos, and how many files are on a drive that isn't connected (those stay in the catalog).
- **Never erased silently:** files only go to the Trash. A file that can't (most network shares, such as megham, have no Trash) keeps its photo, and an alert offers Keep or Delete Immediately, as Finder does. The XMP sidecar goes to the Trash with the last photo of its name in the folder.
- **Virtual copies and stacks:** a picked virtual copy only leaves the catalog; the file it shares stays. An Edit In or AI result stacked on a removed photo stays in the catalog as a photo of its own.
- **After:** the next photo in the list is shown, as in Lightroom.

### Filmstrip (decided Oct 27, 2026)

Rosh asked for Lightroom's Filmstrip: a bottom drawer with the thumbnails of the current list.

- **What it shows:** the photos of the current source (All Photographs, a volume, folder, collection or import entry) with the filter bar applied, in the same order as the grid.
- **Header (AT-018, Oct 31, 2026; design by Antigravity in Google Stitch, `~/RoshProjects/Atelier/design/filmstrip/`):** a 28 pt bar in the theme's chrome color.
  - Left: the **source pop-up** (icon, source name, photo count, ▾), as Lightroom Classic's Filmstrip source indicator. Its menu lists All Photographs (with count), the eight most recent import entries (with counts), collections, and each drive as a submenu with "All Photos on <drive>" and its folders (offline drives say so). Choosing one changes the Library source and keeps the current view (Grid, Loupe or Develop). Then "n selected" (when more than one), "n of N" for the current photo and its filename (plus "Copy n" for a virtual copy), truncated in the middle.
  - Right: a **Filters** pop-up with the same rules as the filter bar (Flag, minimum Rating, Color Label, Edits) and Clear Filters. When a rule is on the button is tinted with the accent color, lists the rules ("Picked · ★3+") and shows an ⓧ that clears them all (search text included; the source and order stay). Saved custom filters are not built yet.
  - Right: a **Sort** pop-up (Capture Time, Import Order, File Name, Rating, Edit Time, then Ascending/Descending) and an arrow button that flips the direction. The order is the Library's, so the grid follows it, and it is restored at launch. Versions stacked on a photo (Edit In, AI, virtual copies) always stay right after it; ties fall back to capture time. Edit Time puts unedited photos first ascending and last descending.
- **Where:** across the full width of the window, under the left panel, the photo area and the right panel, as in Lightroom Classic. It is shown in Grid, Loupe and Develop.
- **Selection:** click selects, ⌘-click adds or removes, ⇧-click selects a run, and double-click opens the photo in Loupe from the grid. When the current photo changes (click, arrow keys) the strip scrolls only if that photo is not fully in view, just enough to bring it in at the edge it was moving toward (centered after a long jump); it never recenters a visible photo (Rosh, Oct 31, 2026). The grid follows the same rule.
- **Focus and selection rings (AT-018, Oct 31, 2026), shared by the grid, the Filmstrip and Cull in every theme:** unselected thumbnails have a faint 1 pt outline; selected ones a 1.5 pt accent-color ring at 65% and a light accent tint; the photo being worked on a solid 2.5 pt accent ring with a 1 pt white line inside it (so it shows on Darkroom's black and Light's gray) and a stronger tint. In Cull, kept photos keep their green ring. Rejected photos are dimmed to 40% everywhere.
- **Thumbnail badges (AT-018, Oct 31, 2026), shared by the grid and the Filmstrip:** icons on dark pills in the corners, as Lightroom's grid cell badges, replacing the old line of text marks. Top left: the photo's number in the Filmstrip and its flag (white flag for picked, red ✕ for rejected). Top right: stack count, virtual copy / AI / Edit In version (with its name on large thumbnails), RAW+JPEG pair, cull group size. Bottom left: stars (a row of gold stars on large thumbnails, "★ n" on small ones) and the color label as a dot. Bottom right: has Develop edits, cropped or straightened, has masks, and an orange warning when the original's drive is offline. Thumbnails narrower than 120 pt show names as icons; under 64 pt (the Filmstrip dragged near its smallest) only the flag, the label, the rating and one mark remain (offline first). An "in a collection" badge was left out (Rosh, Oct 31, 2026). Hovering a thumbnail shows its file name and what its badges mean.
- **Collapse and open:** a small arrow tab centered on the bottom edge (▾ to hide, ▴ to show), View > Show Filmstrip, or F6.
- **Cells (AT-018 design, Oct 31, 2026):** landscape 3:2 cells filled edge to edge with the photo (cropped to fit, rounded 5 pt), 8 pt apart, with 8 pt side and 6 pt top/bottom margins in the strip; 138 × 92 pt at the default height. The photo's number sits in a small circle (accent-colored on the current photo).
- **Size:** drag the Filmstrip's top edge to make thumbnails bigger or smaller (56 to 220 pt; default 104, which gives 92 pt cells). No −/+ size slider in the Filmstrip: the edge drag does the same job (Rosh, Oct 31, 2026). The grid has the slider instead: − and + at the right of the filter bar, 120 to 320 pt, remembered.
- **Remembered:** open or collapsed, and the height, are kept between launches.
- **Right-click menu (Oct 27, 2026):** right-click or Control-click a thumbnail for the same photo menu as the grid, loupe and Develop (Open in Loupe, Edit in Develop, Create Virtual Copy, Edit In, AI, Show in Finder, Set Rating, Set Flag, Set Color Label, Develop Settings, Apply Develop Preset, Match Look, collections and import entries, Write XMP Metadata, Export, Remove Photo…). As in Lightroom, it acts on the Filmstrip selection in every view, Loupe and Develop included; a right-clicked photo outside the selection becomes the selection first.

### Masking (decided Oct 27, 2026)

Rosh asked for Lightroom's graduated, radial and brush adjustments, edited through masks, the way Lightroom Classic does it.

- **Open:** the Masking button (dashed circle) in the tool strip under the histogram, Shift+W, or one of the tool keys: M for Linear Gradient, Shift+M for Radial Gradient, K for Brush. Opening Masking closes Crop and AI. The photo zooms as in Develop (the zoom bar, Z, pinch or ⌘-scroll); scroll, hold Space and drag, or drag on empty photo to move around while zoomed. Masking draws on the same photo view as Develop rather than a copy of it, so opening or closing it never changes the zoom or the spot in view (decided Oct 29, 2026). Pins and handles stay the same size on screen and follow the photo as it zooms; the brush scales with it. Esc or Done (Return) closes it; the masks keep working after it closes.
- **Masks panel:** at the top of the Masking section, a list of the photo's masks ("Mask 1", "Mask 2", in creation order, renameable by double-click). Each mask lists its parts (components) with a small icon and add, subtract or intersect badge. Create New Mask offers Brush, Linear Gradient, Radial Gradient, Luminance Range, Select Subject and Select Object. With a mask selected, Add and Subtract offer the same list; Intersect is in the mask's right-click menu (as in Lightroom: Intersect Mask With). Each mask has an eye to hide its effect, and a right-click menu with Rename, Duplicate, Invert, Intersect Mask With, and Delete. A part's right-click menu has Invert, Switch to Add / Subtract, and Delete. Delete removes the selected part (the whole mask when it was the last part).
- **Show Overlay:** a checkbox (and O) tints the selected mask red on the photo, so it is clear where the adjustment lands.
- **Linear Gradient:** drag on the photo from where the adjustment is full to where it fades out (as in Lightroom: the drag's start side gets 100%; checked Oct 30, 2026). Three lines show the start, middle and end. Drag the pin in the middle to move it. As in Lightroom, drag an outer line anywhere along it to move that line square to itself (widen or narrow that side, angle kept), and drag the center line anywhere along it to turn the gradient around its pin; the pointer shows up/down or left/right over an outer line and the rotate cursor over the center line. The round end handles also stay and move that end freely (Atelier extra).
- **Radial Gradient:** drag from the center outward to draw an ellipse. Drag the pin to move it, the four edge handles to resize it, and the round handle above it to rotate it. Feather (0 to 100, default 50) softens the edge; the inner dashed ellipse shows where the full effect ends. By default the adjustment is inside; Invert puts it outside.
- **Brush:** paint on the photo. Size, Feather and Flow sliders, and Paint / Erase (or hold ⌥ to erase while painting). [ and ] change the size, Shift+[ and Shift+] the feather. The cursor shows the size, with an inner circle for the feather. The stroke always reaches where the mouse was released.
- **Luminance Range:** keeps the parts of the mask whose brightness falls in a range (two sliders, 0 to 100) with Smoothness for the falloff. Usually added with Intersect to limit a gradient to the sky or the shadows.
- **Select Subject:** finds the main subject (people, animals, objects in front) with Apple's Vision framework on the Mac. Invert it to adjust the background.
- **Select Object:** drag a box around something; Vision looks only inside the box, so smaller subjects are found too. Drag the pin to move the box. Select Subject and Select Object have a Feather slider (default 20) to soften Vision's hard edge, and the panel says so when Vision finds nothing.
- **Soft edges:** feathered masks keep their in-between values all the way to the render, so a 50% feather looks like one.
- **Combining parts:** Add unions a part into the mask, Subtract cuts it out, and Intersect keeps only where both overlap.
- **Adjustments per mask:** under the list, the selected mask's sliders, as in Lightroom: Amount (0 to 200%, scales all of the mask's sliders), Temp, Tint, Exposure, Contrast, Highlights, Shadows, Whites, Blacks, Texture, Clarity, Dehaze, Saturation, Sharpness and Noise. Temp and Tint go the Lightroom way: raising Temp warms (yellow), raising Tint adds magenta. Only one Invert checkbox shows at a time, for what is selected: a part's Invert sits with that part's settings, and the whole mask's Invert sits under Amount when the mask row itself is selected (decided Oct 30, 2026). Double-click a slider's name to reset it; Reset Sliders clears them all.
- **Where it sits in the pipeline:** masks are applied after the global adjustments and before vignetting and grain (pipeline step 7). Masks are tied to the photo, not to the frame: they stay on the same spot when the crop, straighten, rotation or flips change.
- **History and storage:** every change is a history step (New Mask: Linear Gradient, Mask 1 Exposure +0.50, Edit Mask 1). Masks are saved in the develop settings JSON with the photo, copied by Copy and Paste Settings and by virtual copies, and optional in presets (the Masks part, off by default, as Lightroom's Masking checkbox). They render in previews, exports, Edit In and AI.
- **Later:** Select Sky and Background, color range, and Lightroom's Auto Mask for the brush.

### Camera-matched RAW look (decided Oct 27, 2026)

Rosh saw a selected photo appear with one look, then turn darker a moment later. The first image was the JPEG preview the camera embeds in the RAW (Nikon Zf and Z6: Picture Control and Active D-Lighting); the second was Apple's RAW engine at default settings, which has none of that processing.

- **Default look:** every RAW starts from the camera's look, like Lightroom's Camera Matching profiles. Atelier compares the embedded preview with its neutral render and fits a tone curve (histogram matching on brightness, smoothed, never moving a tone by more than 30%) and a saturation factor (0.85 to 1.35). It is applied right after decode (pipeline step 1), before any of the user's adjustments, so sliders at zero show the camera's look.
- **Everywhere:** Develop, Before/After, the histogram, masks, the loupe preview, thumbnails of edited photos and exports all use it, so the grid's embedded thumbnail, the loupe and Develop agree and nothing visibly swaps.
- **No usable preview:** files without an embedded preview (or with one of a different shape) keep Apple's render. JPEG, HEIC and other non-RAW files are unchanged.
- **Previews:** previews from before this change are rebuilt once on first launch.
- **Profile choice:** built Oct 27, 2026 as the Profile menu in Basic (see Profile, Lens Corrections and Transform).

### Profile, Lens Corrections and Transform (decided Oct 27, 2026)

Rosh asked whether a camera profile is worth having, and for Lightroom's perspective tools: corrections from the lens profile, Upright, and guides drawn on the photo.

- **Profile (top of Basic):** a Profile menu like Lightroom's. Camera Matching (the default; the camera-matched look above, fitted per photo so it follows the Picture Control and Active D-Lighting each shot was taken with) and Apple Neutral (Apple's RAW render with no camera look: flatter, with more highlight room, a starting point for heavy edits). Non-RAW files show the menu dimmed. The profile is applied at decode, under all the sliders, and is a history step ("Profile: Apple Neutral"). Fixed per-camera profiles (one look for every Zf or Z6 file, or a ColorChecker profile for artwork) come later; the per-photo match already follows each shot's camera settings, so they are not needed now.
- **Lens Corrections panel** (after Detail, as in Lightroom Classic):
  - **Remove Chromatic Aberration** (checkbox above Enable Profile Corrections, off by default; added Oct 29, 2026): lines up the red and blue channels with green to remove lateral chromatic aberration (red-cyan and blue-yellow edges that grow toward the corners). As in Lightroom it needs no sliders: the amount is measured from the photo itself, by finding the red and blue scales about the center that best line up their edges with green's (searched to ±0.3%, measured once per file on a 2,000 pixel render and reused by every render of that file, so the proxy, the full-size view and exports agree). Works on RAW and non-RAW files; it runs before Defringe and the lens warp. History step "Remove Chromatic Aberration" / "Chromatic Aberration: Off".
  - **Profile:** Enable Profile Corrections (on by default for RAW files) applies the distortion and vignetting corrections Apple's RAW engine has for the camera and lens, which for Nikon Z files come from the correction data the camera writes into the NEF. The panel shows the lens name from the file. When the RAW engine has no corrections for the file (or it is not a RAW), the checkbox is dimmed with "No lens corrections for this photo".
  - **Manual:** Distortion (-100 to 100; positive removes barrel distortion, negative removes pincushion) and Lens Vignetting Amount (-100 to 100; positive brightens the corners) with Midpoint. These act on the whole uncropped photo around its center, unlike Effects > Post-Crop Vignetting.
  - **Defringe** (between Distortion and Vignetting, as in Lightroom Classic's Manual tab; added Oct 29, 2026): removes purple and green fringes (longitudinal chromatic aberration, mostly from wide apertures) along high-contrast edges.
    - Purple Amount and Green Amount (0 to 20, default 0): higher removes more. Amount sets how far from a strong light-dark edge a pixel can be (about 1 to 11 full-size pixels) and how readily an edge counts. A fringe pixel loses its color and keeps its brightness.
    - Purple Hue and Green Hue: a two-ended range slider (0 to 100) on a strip of the colors it can cover, dimmed outside the range. Purple runs from blue through violet to magenta (defaults 30/70), green from yellow through green to aqua (defaults 40/60, narrow to protect foliage). Drag an end to widen or narrow the range, or between the ends to move it; the ends stay at least 10 apart. Double-click the name to reset the range.
    - Only pixels in a Hue range, saturated enough to be a color, and near a strong edge change, so purple or green objects away from edges keep their color. Hue is judged on display-like values (sRGB primaries), so the ranges match the colors on the sliders.
    - Fringe Color Selector (eyedropper next to the Defringe heading): the photo stays zoomable and pannable while it is out, with a crosshair and a hint over the photo. Zoom in and click a fringe: Atelier looks at the pixels around the click (on the full-size render when zoomed in), takes the most saturated one, and if it is purple or green, centers that color's Hue range on it (20 wide) and sets its Amount to 5 if it was 0, then puts the selector away. Anything else shows "Cannot set the purple or green fringe color. Click on a purple or green fringe." and the selector stays out. Esc or the eyedropper puts it away.
    - Option-drag: Amount shows white with the fringes being removed in their color; Hue shows black outside the range so you can see which colors it covers.
    - Before/After leaves Defringe and chromatic aberration out, like the other color edits. Presets carry both in the Lens Corrections part.
  - **Later:** choosing a lens profile by hand, and the masks' local Defringe slider.
- **Transform panel** (after Lens Corrections):
  - **Upright:** buttons Off, Auto, Level, Vertical, Full and Guided. Atelier finds straight lines in the photo (after lens corrections) and solves for the tilt that makes them straight: Level makes horizontal lines level (rotation only); Vertical also makes vertical lines parallel (vertical perspective and rotation); Full also corrects horizontal perspective; Auto does the same as Full but holds back when the lines are weak, so it never warps a photo hard on thin evidence. If too few lines are found, the button reports "Not enough straight lines found" and nothing changes. Upright's correction is stored with the photo, so it never changes on its own; clicking the mode again recomputes it. As in Lightroom, applying an Upright mode (including Guided's first correction) resets the crop's cut and straighten angle (rotations and flips stay) and the manual Transform sliders; ⌥-click the button to keep them.
  - **Guided:** the Guided button (or Shift+T) opens the guides tool on the photo as edited, crop included, as in Lightroom: drag along an edge that should be vertical or horizontal to draw a guide (up to four). Each guide is treated as vertical or horizontal by which it is closer to. As in Lightroom, one guide changes nothing; the photo straightens once there are two guides and updates as each further guide is drawn or moved. Every guide ends exactly straight, as in Lightroom: with three guides the tilt and rotation solve them exactly, and with two vertical and two horizontal guides a slight slant of the verticals takes up what one camera turn cannot (imprecise guides, or a focal length the file gets wrong). While a guide is drawn or its end is dragged, a loupe beside the pointer shows the photo magnified 3× with a crosshair; Transform > Show Loupe or the O key turns it off (remembered). As in Lightroom, the corrected photo stays in its frame, so a strong correction can push part of it, guide ends included, out of view: lower Scale, or ⌘⌥-drag the photo to move it through X and Y Offset (with Shift, in one direction only). Better than Lightroom: a Show Whole Photo checkbox in the Guided controls (off by default, remembered) zooms the view out to the whole corrected photo, uncropped, so every guide shows; it changes only the view, never the edit. Drag a guide's ends to move them; select a guide and press Delete to remove it. Two vertical guides fix converging verticals (the main use for buildings and artwork); add horizontal guides to also fix the horizontal perspective. Esc or Done closes the tool. (Decided Oct 29, 2026, after Rosh found Guided didn't behave like Lightroom; Rosh wants Lightroom's behavior as the starting point.)
  - **Manual sliders**, added on top of Upright: Vertical (-100 to 100; negative widens the top, for buildings shot from below), Horizontal (-100 to 100), Rotate (-10° to 10°), Aspect (-100 to 100; positive stretches width), Scale (50 to 150%), X Offset and Y Offset (-100 to 100).
  - **Constrain Crop:** off by default. As in Lightroom, turning it on sets the crop to the largest rectangle with no empty edges, keeping the crop's shape (the photo's own aspect ratio when uncropped). Its position is searched as well as its size, because a perspective correction leaves an uneven shape and a centered crop would waste photo. Whenever the correction changes (an Upright mode, a guide, a Transform or Lens Corrections slider), the crop is found again, so it also grows back when the correction gets milder; other edits, and a crop drawn by hand, only keep it inside the photo. While it is on, the crop stays inside the corrected photo: the Crop tool stops a drag or a straighten at the edge, and any later Upright, slider or turn shrinks the crop again if gray would show. The photo is cropped at once in the main view and in the Guided tool. Turning it off leaves the crop as it is. With it off, the areas the correction leaves empty show as light gray, as in Lightroom. Photos saved when Constrain Crop enlarged the photo instead get the crop the next time they are opened. (Changed Oct 29, 2026: it used to enlarge the photo.)
- **Pipeline:** profile corrections at decode, then manual lens vignetting and distortion, then the Transform, all in step 1, before every adjustment, the masks and the crop. Masks, the crop and Select Subject work on the corrected photo, so changing the Transform after drawing a mask keeps the mask on the same spot of the frame.
- **Storage and sharing:** all of it is part of the develop settings (history steps, Copy/Paste Settings, virtual copies). Presets get Profile, Lens Corrections and Transform parts, off by default, as in Lightroom's preset dialog. Before/After keeps the lens corrections and Transform, like the crop, so the two line up.

### Match Look to a Reference (decided Oct 27, 2026)

Rosh asked for color matching from a reference picture: give a photo the look of another image (a downloaded photo, a film still, or one of their own edited shots). Design discussion: https://claude.ai/artifact/1wZzQU68nnQv4qpzVR5Rj6

- **Result is ordinary sliders:** the match works out Develop settings (White Balance, Exposure, the RGB Tone Curve, Saturation, HSL and Color Grading) that make the photo's render look like the reference. Applying it is one history step ("Match Look: <reference name>") that can be edited, undone, copied, synced or saved as a preset like any other edit. No generative AI touches the pixels, so the licensing rule does not apply. No exact-match 3D LUT mode: everything stays editable with sliders.
- **Dialog first:** Develop > Photo > Match Look to Reference… (⇧⌘M) opens the Match Look dialog; so does Match Look to Reference… in the right-click menu on photos (grid, loupe, filmstrip and Develop), which opens the clicked photos in Develop first (added Oct 27, 2026 at Rosh's request). The reference is picked only inside the dialog, not from the filmstrip or a right-click menu:
  - **Choose File…** (the main path): any image on the Mac (JPEG, PNG, HEIC, TIFF, or a RAW's embedded preview). Dragging an image from Finder onto the reference slot does the same.
  - **Recent References:** the last 8 reference files. Only each file's location and a small thumbnail are remembered; the file is not copied into the catalog. A moved or deleted file shows as missing.
  - **Use a Photo from the Catalog…:** a secondary choice, for matching a set to a shot already edited; the catalog photo is used with its current edits.
- **Match and preview inside the dialog:** the reference on the left and a live preview of the open photo on the right; press and hold the preview to see Before. Checkboxes for White Balance, Tone and Color (all on by default). Strength (0 to 100, default 100) blends between the photo's current settings and the matched ones, and the preview follows it. **Show Differences** (next to Strength) lists each slider Apply will move, from its current value to the matched one ("Saturation Green +0 → +24"). Nothing changes on the photo until Apply; Cancel leaves it exactly as it was. Strength is baked in on Apply; to change it later, edit the sliders or run the match again.
- **Match Areas (optional):** a toggle that shows a box on the reference and a box on the photo. Drag each box over the parts that should match (skin to skin, sky to sky). The fit weighs the boxed areas most (three quarters of the weight) and the rest of each image a little, so the whole photo still moves sensibly. This handles references whose content differs from the photo.
- **More than one photo:** when several photos are selected in the filmstrip, the dialog offers Same settings (fit once on the open photo and apply those values to all) or Match each photo (fit each photo to the reference on its own, for mixed light; runs in the background with progress and Cancel in the status bar). Each photo gets its own history step.
- **How the fit works (Phase 1, HSL and refinement added in Phase 2):** both images are measured at about 384 pixels in Oklab, a perceptual color space, after the photo's current profile, lens corrections and crop. In order: White Balance moves Temp and Tint until the photo's average midtone color matches the reference's; Exposure moves the median brightness (at most ±2 EV); the RGB Tone Curve is fitted by histogram matching on brightness (smoothed, rising, never moving a tone by more than 30%, five points so it stays editable); Saturation matches the reference's typical chroma (-60 to +60); HSL moves each of the eight bands' hue (±50), saturation (±60) and luminance (±50) toward the reference's average color in that band, skipping bands with under 2% of either image's color; Color Grading Shadows and Highlights take any remaining color difference between dark and bright tones (split toning). Last, a refinement pass nudges Temp, Tint, Exposure and Saturation one at a time and keeps a nudge only when it brings the photo's whole color distribution closer to the reference's (sliced Wasserstein distance in Oklab), so the sliders fitted one by one settle together. Each step renders the photo through the real Develop pipeline and corrects itself against that render, so the result reflects what the sliders actually do. Every value is clamped, so an odd reference can't wreck the photo.
- **Later phases:** Protect Skin Tones and automatic subject/background areas from the Select Subject mask (Phase 3). AI color-transfer models stay experiments only.

## Catalog and library management

The catalog never modifies an original file. Every photo is a database record pointing at a file by volume ID and relative path, so moving or remounting a drive does not break links.

### Import modes

1. **Reference in place.** Files stay where they are (local or NAS). The app records the volume UUID, relative path, file size, modified time and a content hash.
2. **Copy to managed library.** Files are copied into a dated folder template (default `YYYY/YYYY-MM-DD Event/`), renamed by an optional pattern, verified by hash after copy, and optionally backed up to a second destination in the same pass.
3. **Watch folder.** A folder is monitored with FSEvents; new files import automatically with a chosen preset (used for tethering and for the ComfyUI output folder).

### Requirements

- Formats: all RAW formats Apple's RAW engine supports, plus DNG, JPEG, HEIC, TIFF, PNG, WebP, PSD (composite only). Video files cataloged with poster frames.
- Import applies a metadata preset (copyright, creator, keywords) and a develop preset.
- Previews: a 256 px thumbnail and a 2560 px preview per photo, generated in the background. Thumbnails come first, from the file's embedded preview when it is large enough, once every file of the import is cataloged; 2560 px previews follow at lower priority, except the photo open in the loupe, which jumps the queue. Moving to another photo in Loupe or Develop never shows the empty background (AT-019, Oct 31, 2026): the last photo stays until the next one is ready, its grid thumbnail shows at once if it is in memory, and the 2560 px preview replaces it, decoded off the main thread. The last eight decoded previews stay in memory, and the photos before and after the current one are decoded ahead. Optional smart preview (lossy DNG, 2560 px long edge) for offline editing.
- Metadata: EXIF, IPTC and XMP read on import. Ratings, labels, keywords and develop settings written to XMP sidecars on demand or automatically, so other apps can read them.
- Photo info in Grid and Loupe (Oct 30, 2026, at Rosh's request, Lightroom Classic as the floor):
  - The right panel (Inspector) uses the same collapsible section headers as Develop's panels (Histogram, File, Camera, Rating and Labels, Keywords, Title and Caption; remembered, with Solo Mode and Expand/Collapse All on right-click). It opens with a histogram drawn from the photo's preview (so it shows the edits), with clipping triangles and the camera settings line under it ("ISO 400   50 mm   ƒ/2.8   1/250 sec"), as in Lightroom's Library module. It only shows; editing is in Develop.
  - File section: File Name, Paired With (RAW+JPEG), Copy Name, Folder, Volume, Dimensions (with megapixels), File Size.
  - Camera section, Lightroom's EXIF set, read from the file: Capture Time, Camera, Lens, Exposure ("1/250 sec at ƒ/2.8"), ISO Speed, Focal Length (with the 35 mm equivalent when it differs), Exposure Bias, Flash, Exposure Program, Metering Mode. A file without camera settings says so.
  - The Loupe's overlay on the photo, like Lightroom's Loupe info: the file name, then capture time and dimensions, then "1/250 sec at ƒ/2.8, ISO 400, 50 mm" and the lens, then rating, flag, label and Offline when any apply.
- Organization: folders mirror disk; collections and collection sets are virtual; smart collections are saved queries; stacks group versions and bursts.
- Import entries: every import lands in a named entry listed in the sidebar (default name: the source folder, or the event name for copied imports). An import can create a new entry or add to an existing one; files already in the catalog join the entry without being imported twice. Entries can be renamed and deleted, and photos added to or removed from them by hand. Removing a photo from an entry, or deleting an entry, never removes the photo from the catalog. The one exception is asked for explicitly: the Delete Import dialog has "Also delete the photos and move their files to the Trash", always unticked when it opens. Ticking it shows a warning with the number of files that go to the Trash (and any on an offline drive that stay), makes Cancel the default button and turns Delete Import into "Delete Import and Files", which works like Remove Photo > Delete from Disk for every photo in the entry (Rosh, Oct 30, 2026).
- **Private imports and collections (AT-023, Oct 31, 2026, Rosh):** some shoots (for example model photoshoots) should be seen only on purpose. This is about deliberate access, not security: files, previews and folders on disk are not encrypted or moved.
  - **The property, per list:** right-click an import entry or collection > **Make Private…** (a one-line confirmation, Rosh: no long text) turns it on; **Make Not Private** turns it off and is only offered while private photos are shown, so removing it already needed Touch ID or the password. Collection sets can't be private. A lock follows a private list's name in the sidebar.
  - **Seeing them, separate from the property (the View menu, Rosh Oct 31):** three choices with a checkmark, listed only while at least one list is private: **Hide Private Photos**, **Show Private Photos…** (with every other photo) and **Show Only Private Photos…** (only private photos and private lists in the grid, Filmstrip and sidebar; All Photographs counts private photos; folders only those holding one). Leaving Hide asks for Touch ID or the Mac's login password (macOS's own prompt, `LAContext` `.deviceOwnerAuthentication`; no Atelier password). Never asked for at launch or on opening a list. While shown, **Hide Private** sits in the sidebar's Library header. On a Mac without a login password a plain confirmation is shown instead.
  - **Hiding again:** **View > Hide Private Photos** or **Hide Private**; after a set time without using Atelier (only Atelier's own key, mouse and scroll events count; Settings > General > Private Photos: 5, 10 (default), 15, 30, 60 minutes or Never); when the Mac or its display sleeps, the screen locks, the screen saver starts or the user switches; and every launch starts hidden. On hiding, a private sidebar item falls back to All Photographs; if a private photo is open or selected, Atelier goes to the grid and closes Export, Match Look, Remove Photo and Cull when they show one.
  - **What hidden means:** a photo that is in any private list, or is a virtual copy, stacked edit or AI result of one, or the other file of its RAW+JPEG pair, is left out of the grid, Filmstrip, every import, collection, folder and volume, search and filters, All Photographs and every count; private lists are left out of the sidebar, the Filmstrip source menu, Organize, Add to Collection/Import and the Import dialog's list; a folder holding only private photos is left out too. Private wins over an ordinary list holding the same photo. Session restore never reopens a private list or photo while hidden. The shown/hidden state is never saved.
  - **Not covered:** a photo already open in another app (Edit In, the HDR app), Finder, and Match Look's recent reference files picked from disk.
- **Catalog-open recovery (Oct 30, 2026):** opening runs off the main thread. If it fails, dismiss the splash and show a native “Couldn’t Open Catalog” screen with the package path and reason, **Try Again**, **Show in Finder** and **Quit**. Retry opens the same location; no deletion, replacement, reset or automatic backup restoration. An existing package missing `catalog.sqlite` but containing previews, backups or other files is an error, not a new empty library. An absent or empty package (including one containing only Finder’s regular `.DS_Store` file) can complete first launch after an interruption. The missing-database message points to the package’s Backups folder without implying a built-in restore command. Library commands and session/quit backups become available only after a successful open. Help remains available. Backup restoration is separate.
- One catalog: a single catalog holds the whole library. Separate sets of photos are kept apart with import entries, folders and collections, not separate catalogs.
- Search: filter bar on any metadata field, combined with AND/OR. Full-text over keywords, titles and captions.
- Duplicate detection by content hash (exact) and perceptual hash (near-duplicates).

### NAS and offline volumes

- Each volume shows online or offline in the sidebar. Offline photos stay browsable through previews.
- Ratings, keywords and develop edits on offline photos are stored in the catalog and synced to XMP when the volume returns.
- Edits that need the original (export, Edit In, AI on full resolution) queue until the volume is online, or run on the smart preview if the user chooses.
- Missing-file finder: relink by hash when files move outside the app.

## Develop module

Edits are a versioned list of parameters stored in the catalog, rendered live on the GPU from the original. Nothing is baked into a file until export, Edit In or an AI step.

### Pipeline order

1. RAW decode and demosaic (CIRAWFilter): white balance, exposure, profile lens corrections, then the profile (camera-matched base look or Apple Neutral), Remove Chromatic Aberration, Defringe, manual lens corrections and the Transform (Upright and the perspective sliders). Non-RAW files get white balance and exposure (with its highlight roll-off) here.
2. Geometry: crop, straighten, rotation and flips, so everything after follows the crop.
3. Tone, in a perceptual (gamma-encoded) space: Highlights and Shadows (local), then one hue-preserving tone curve for Contrast, Whites, Blacks, the region curve and the RGB curve (with Refine Saturation below 100 the RGB curve runs as its own pass), then the Red, Green and Blue curves per channel. Values beyond white or outside sRGB continue with slope 1 instead of clipping.
4. Presence: Dehaze, Clarity, Texture.
5. Color: Vibrance, Saturation, then HSL, Point Color (or the B&W Mix) and color grading, in one 32³ color cube that spans Display P3, so wide-gamut colors are not clipped to sRGB.
6. Detail: noise reduction, then sharpening with masking.
7. Local adjustments: each mask carries its own subset of steps 3 to 6.
8. Effects: Glow, post-crop vignetting, grain.
9. Output transform: working space (linear Rec. 2020) to display or export space.

### Tools and requirements

- Live preview at 60 fps on a 2560 px proxy; full-resolution render once the photo is zoomed past fit, and for export. A mouse drag updates the control and live photo as it moves. It saves one history step when released, including when the mouse pauses during the drag.
- The right column sits beside the photo and below the toolbar (never under it), like Lightroom's panel strip. Drag its left edge to resize it (280 to 560 points); its content always fits the column.
- Panels follow Lightroom's layout and order in the right column, each collapsible, remembered between sessions, with a dot and a reset button when it has edits. Right-click a panel header for Solo Mode (one panel open at a time), Expand All and Collapse All.
  - Panel switches (Oct 29, 2026, as in Lightroom Classic): every panel but Basic has an on/off switch in its header (Tone Curve, HSL / Color, Color Grading, Detail, Lens Corrections, Transform, Effects). Off takes away everything the panel does and keeps its settings: the curve and region sliders, HSL or the B&W Mix, the wheels, sharpening and noise reduction, profile corrections, chromatic aberration, Defringe, distortion and lens vignetting, Upright and the Transform sliders, vignetting and grain. The panel's controls are dimmed but still work, and moving one turns the panel back on, so an edit never goes unseen. A panel that is off shows the edit dot, and its reset arrow resets it and turns it on. The switches are stored with the photo, so previews, export, Edit In, history (each switch is a step), copy and paste follow them; a preset carries the switch of each panel it includes. A crop that Constrain Crop fitted stays as it is when Transform is turned off. One mechanism serves every panel: the renderer and the lens geometry read the settings through `applyingPanelSwitches()`.
  - Histogram (reworked Oct 30, 2026 at Rosh's request, Lightroom Classic as the floor): RGB, from the current render.
    - Under it, how the photo was taken, read from the file's EXIF as in Lightroom: ISO, focal length, aperture and shutter speed ("ISO 400   50 mm   ƒ/2.8   1/250 sec"). Hovering the line shows the camera, lens and exposure compensation. A file without camera settings says so.
    - Clipping triangles in the top corners: dim when nothing clips, lit in the color of the clipped channels (white when all three clip). Settings > Develop > Panels can also show the clipped share next to a lit triangle (from 0.5%). Click a triangle to show that clipping on the photo: pure white (all three channels at 255) red and pure black (all three at 0) blue. A saturated color with one channel at 0 or 255 (a deep blue sky, a red flower) keeps its detail and is not marked; the triangle's color shows those channels and its tooltip says so (fixed Oct 30, 2026 after Rosh saw blue on bright colors); J or Develop > Show Clipping turns both on or off. The overlay marks exactly the pixels the triangles count, is never painted into previews or exports, and is left off the Before view, the crop tool and the AI tool. It starts off on each launch.
    - Tone regions: the pointer over the histogram lights the region under it (Blacks, Shadows, Exposure, Highlights, Whites, left to right) and the line underneath shows that slider's name and value. Dragging left or right changes the slider, a whole width moving it by half its range; double-click a region to reset its slider. The change is one history step like any slider drag.
  - Basic: Profile (Camera Matching, Apple Neutral), White Balance (Temp, Tint), Tone (Exposure, Contrast, Highlights, Shadows, Whites, Blacks), Presence (Texture, Clarity, Dehaze, Vibrance, Saturation).
    - White Balance, as in Lightroom: a WB menu (As Shot, Auto, and for RAW files Daylight, Cloudy, Shade, Tungsten, Fluorescent and Flash with Lightroom's Temp and Tint values; Custom once the sliders move) and the White Balance Selector (the eyedropper button or W): click something that should be neutral gray or white and Temp and Tint are set so it is; the selector puts itself away after one click, Esc cancels. The photo zooms and pans while it is out, like every color picker (see Sliders, group headings and color pickers). Develop > Auto White Balance (⇧⌘U) and the menu's Auto make the photo's nearly gray colors neutral. Both measure the photo through the real render and take a moment, with a spinner by the menu. RAW Temp is in Kelvin (2000 to 50000) and Tint shows the camera's tint plus the change (−150 to +150). JPEG, HEIC and TIFF files have no real Kelvin, so Temp shows −100 to +100 (0 is as shot) and Tint −100 to +100.
    - Exposure on JPEG, HEIC and TIFF files rolls the brightest tones off toward white instead of clipping them (a soft shoulder above about 80% brightness, keeping each color's hue), like the highlight roll-off in Adobe's exposure curve. RAW files get theirs from the RAW engine.
    - Auto (next to the Tone heading) sets Exposure, Highlights, Shadows, Whites and Blacks from the photo's histogram, measured through the real render: the median brightness goes to about 46%, Whites brings the brightest 0.5% to white, Blacks the darkest 0.5% to black (never lifting them), Highlights comes down when much of the photo is near white and Shadows comes up when much is near black. Contrast is left alone. Shift-double-click a Tone slider's name for Auto on that slider alone, or Temp or Tint for Auto white balance, as in Lightroom. It is one history step ("Auto Tone", "Auto Whites").
    - Highlights and Shadows work locally, as Lightroom's do: a wide edge-aware base (the same guided filter as Clarity, about 100 full-size pixels) decides how bright each area is, so a whole sky or shadow moves together and its detail rides along unchanged. Shadows peaks around 25% brightness and Highlights around 75% (Adobe's targets are 10 to 30% and 70 to 90%); pure black and white stay put, and both directions of each slider work the same way. Each channel moves by the same amount in gamma-encoded values, so lifted shadows keep their hue without turning noise into color. Not done yet: pulling detail back from a RAW's headroom above white (this needs testing with real NEFs).
    - Clarity and Texture change local contrast on brightness only, so colors keep their hue and saturation. The photo's brightness is split into a smooth base and the detail on top with an edge-aware (guided) filter, so positive values add no halos and negative values smooth surfaces while edges stay sharp, rather than blurring the photo. Clarity works on wide areas and is weighted to the midtones (Lightroom: "biased towards the midtones"); Texture on medium-sized detail such as skin, bark and foliage. Their sizes are measured in the full photo's pixels, so a crop, the live preview and an export look the same.
    - Dehaze works like Lightroom's physical haze model: it estimates the haze color and how much haze lies over each area (dark channel prior, refined along edges with a guided filter), then removes it (positive) or adds more where the photo is already hazy (negative). Dark, clear areas and anything brighter than the haze barely change, so it never crushes shadows to black or clips the sky.
  - Tone Curve (Parametric and Point views, reworked Oct 30, 2026 to match Lightroom Classic):
    - Parametric: the region curve over the histogram with Highlights, Lights, Darks and Shadows sliders. Three split-point triangles under the graph move where each region ends (5 to 95, kept 5 apart). Dragging up or down on the graph moves the region under the pointer, which is shaded. The region curve is a smooth rising curve through the middle of each region and is applied after Basic tone; black and white never move (the earlier bumps lifted black to 6% at Shadows +100).
    - Point: an editable curve for RGB, Red, Green and Blue, drawn over that channel's histogram. Click to add a point (up to 16, as in Lightroom) and drag it; drag a point off the graph or double-click it to remove it. Input and Output fields (0 to 255) show and type the selected point; with the pointer over the graph the arrow keys nudge it (⇧ for 10). The ••• menu and right-click offer Linear, Medium Contrast and Strong Contrast, saved curves (Save Curve…, Delete Saved Curve), Copy and Paste a channel, Reset the channel or all channels, Snap to Grid and Show All Curves. The overall result of Basic tone and the region curve shows as a faint line under the RGB curve.
    - Refine Saturation (0 to 100, default 100; shown when the RGB curve is not a straight line): at 100 the RGB curve changes saturation along with brightness, as Lightroom does; lower values hold that back toward a brightness-only change.
    - Basic tone (Contrast, Highlights, Whites, Blacks), the region sliders and the RGB curve keep each color's hue, as Lightroom does: the curve moves the brightest and darkest of a pixel's red, green and blue, and the middle one keeps its place between them (Adobe's DNG reference method). An orange gets brighter or darker and more or less saturated with Contrast, but never turns red or yellow. The Red, Green and Blue curves work on their own channel, so they can still shift color on purpose.
  - HSL / Color (reworked Oct 30, 2026): Mixer and Point Color views, as Lightroom's Color Mixer.
    - Mixer: eight bands (Red, Orange, Yellow, Green, Aqua, Blue, Purple, Magenta) with Hue, Saturation and Luminance, shown one channel at a time or All, on colored slider tracks. The bands work in Oklab lightness, chroma and hue: Saturation −100 leaves a color's brightness as the eye saw it (HSL math turned deep blue 50% gray), Luminance moves perceived brightness in proportion to how colorful the color is, and grays and noise-level tints (near-blacks, shadow noise) are left alone. A change that would leave Display P3 lowers chroma instead of clipping, so it keeps its hue.
    - Point Color: up to four swatches. Pick a color with the eyedropper, then Hue (±30°), Saturation and Luminance shift the colors near it. Range widens or narrows which colors count as near (by hue, lightness and chroma, with a soft edge); Uniformity (beyond Lightroom, from Capture One's skin tone tool) pulls those colors toward the picked one to even out blotchy skin or a patchy sky. Visualize Range shows only the selected colors, the rest gray. Right-click a swatch to delete it.
    - Targeted Adjustment Tool (the target button in Tone Curve, HSL and B&W Mix): drag up or down on the photo to move the sliders for the tone or color under the pointer, as in Lightroom. In the Parametric curve it moves the regions; in the Point curve it adds or moves a point on the shown channel; in HSL it moves the shown channel's bands (in All, pick the channel from its menu). Each drag is one history step; Esc puts it away.
  - Color Grading (reworked Oct 29, 2026 at Rosh's request; Lightroom Classic is the floor, with additions beyond it):
    - Views: buttons for 3-Way (Midtones centered above Shadows and Highlights, each with a Luminance slider) or one large wheel at a time (Shadows, Midtones, Highlights or Global) with Hue, Saturation and Luminance sliders that take typed values. The view is remembered. Then Blending and Balance.
    - Each wheel, as in Lightroom: a hollow inner dot (filled with the tint it gives) for hue and saturation, a solid dot on the rim for hue only, and a spoke from the center through the dot to the rim. Grabbing the inner dot moves it from where it is (it never jumps); a click elsewhere on the wheel puts it there. Dragging along the spoke holds the hue (a soft constraint) until the pointer moves well off it. Shift-drag changes saturation only, ⌘-drag hue only, ⌥-drag moves at a tenth of the speed for fine adjustment. Double-click inside a wheel resets hue and saturation; double-click its name resets the whole wheel. With the pointer over a wheel, ←/→ turn the hue and ↑/↓ change saturation (⇧ for steps of 10).
    - Right-click a wheel: Reset Hue and Saturation, Reset Luminance, Reset (wheel), Copy and Paste the wheel's settings, Reset All Color Grading. Press and hold a wheel's eye button to see the photo graded by that wheel alone. The panel header's on/off switch turns all Color Grading off to compare, keeping the settings (the shared panel switch; see Panel switches).
    - Beyond Lightroom: each wheel shows faint dots where the photo's colors in its tonal range sit (a small vectorscope from the current render) and small rings where the other wheels' tints are. A graph under Blending and Balance shows the three tonal ranges from black to white. A color picker (eyedropper in the panel) sets a wheel so the clicked spot's color cast turns neutral: in 3-Way it picks Shadows, Midtones or Highlights by the spot's tone, in a single view that wheel; Esc cancels.
    - How tints render: the hue numbers are Lightroom's (0 red, 60 yellow, 120 green, 240 blue), but each tint is built in Oklab so the same Saturation looks equally strong at every hue; the hues between red, yellow, green, cyan, blue and magenta turn evenly in Oklab. Luminance raises or lowers lightness with a roll-off toward white and black, so it never clips (lightening shadows lifts and tints black, darkening highlights tints white, as in Lightroom). A tint that would leave the screen's colors is shortened rather than clipped, so it keeps its hue.
  - Detail: Sharpening (Amount 0 to 150, Radius 0.5 to 3.0, Detail 0 to 100 default 25, Masking 0 to 100), Noise Reduction (Luminance, Color). Detail below 25 holds back halos, above 25 brings out fine texture; Masking keeps sharpening to edges (0 sharpens everywhere, 100 only the strongest edges). Detail and Masking added Oct 28, 2026; at their defaults the render is unchanged.
  - Effects: Post-Crop Vignetting, Glow, Grain (Type default Standard, Amount, Size default 25, Roughness default 50).
    - Post-Crop Vignetting (reworked Oct 30, 2026, as Lightroom's): Style (Highlight Priority, Color Priority, Paint Overlay), Amount, Midpoint, Roundness, Feather (default 50) and Highlights. The shape follows the crop (an ellipse with its proportions at Roundness 0; positive toward a circle, negative toward a rounded rectangle). Highlight Priority darkens like lower exposure but holds back bright tones; Color Priority keeps hues; Paint Overlay mixes in black or white. Highlights brings bright areas back in darkened corners.
    - Glow (beyond Lightroom Classic; Camera Raw and Luminar have one): Style (Diffusion, Bloom, Halation), Amount, Range (how bright a tone must be to glow), Spread (how far it reaches, a share of the photo's size) and Warmth. Halation is film's red-orange glow around bright highlights (CineStill 800T).
    - Grain behaves like Lightroom's film grain (reworked Oct 29, 2026; the earlier version looked like sparse dots in bright areas only). It is monochrome: it changes brightness, not color, and is strongest in the midtones, fading toward pure black and pure white, which stay clean. Size sets the particle size in the photo's own pixels (about 1.7 px at 25, 8 px at 100); above 25 the photo is softened slightly, as in Lightroom, so large grain replaces fine detail. Roughness 0 gives even, regular grain; higher values make it clump and vary in strength across the frame.
    - Grain Type (added Oct 30, 2026; beyond Lightroom, after DxO FilmPack's grain that differs by film stock): a menu above Amount. **Standard** (default) is the Lightroom-like grain above, so existing edits look as they did. **Fine** is the small, tight, crisp grain of slow film (Ektar, Velvia, Pan F). **Cubic** is the larger, sharp-edged, clumpy grain of classic cubic-crystal film (Tri-X, HP5, Gold, Superia), reaching further into the shadows. **Tabular** is the smooth, soft, even grain of T-grain film (Portra, T-Max, Delta, Vision3), leaving shadows and highlights cleaner. Every type has the same strength for a given Amount, so only the character changes; Size and Roughness still apply on top of each type's own particle size and clumping. DxO's 153 measured film stocks are not copied (they come from DxO's lab measurements); built-in film presets set the type that fits their stock instead, and the rest leave Standard. One kernel serves all types (`FilmGrain.Look`).
    - The pattern is fixed, so every render of a photo shows the same grain. Like Lightroom, grain is judged at 100%: on the fit view and smaller exports it is weaker, as it would be if the full-size render were shrunk, so the live preview matches the export.

Double-click the name to reset, click the value to type one. Temp, Tint, Vibrance, Saturation and the HSL sliders have colored tracks; Temp moves in perceptual (logarithmic) steps.

#### Keyboard focus in Develop (decided Nov 9, 2026)

Rosh asked for keyboard control in Develop; each point was checked against macOS and Lightroom Classic.
- **Sliders:** clicking, dragging or Tabbing to a slider gives it focus; ← → ↑ ↓ move it 1/200 of its track (never less than one step), ⇧ five times that. With a slider focused, ← and → move the slider, not the photo (the Mac way; Rosh chose it over Lightroom's "↑↓ only" on Nov 9, 2026). Esc or a click on the photo gives the arrows back to the photo. Quick presses coalesce into one history step like a drag. Every slider gets this through `SliderRow` (plus the preset Amount and Color Grading luminance sliders).
- **Presets list:** clicking a preset or group, or ⌃Tab to the left column, gives the list focus. ↑ ↓ move a highlight and preview the preset in the Navigator (as hovering does, so arrowing never fills History); Return or Space applies; → opens a group or enters it, ← closes it or goes up to it (Finder's keys); Esc puts the preview away.
- **Tab** moves control to control within the area that has focus (top to bottom, wrapping; ⇧Tab goes back), the Mac standard; once ⌃Tab has reached an area, Tab walks its controls (Rosh, Nov 9, 2026). Panel headers are Tab stops too, so a closed panel can be reached and opened from the keyboard (Return or Space opens or closes it, → opens, ← closes); the order is where controls sit in the column, top to bottom, whatever the scroll. Tab never leaves the area: a text field in it is a stop too (Search Presets in the Presets area; Esc leaves it), but ⌃Tab lands on the list, not the field. Moving between photos: while ← → come quickly the cached preview shows (with its histogram) and nothing is decoded; the photo stopped on decodes once they rest, and the photos either side of the open one are decoded in the background so the next ← or → opens at once, as in Lightroom. A mouse click selects an area for the keyboard just as ⌃Tab does (Rosh, Nov 9, 2026): a click on a control focuses it, a click elsewhere in a panel focuses the control used last there (or the top one), and a click on the photo or Filmstrip gives ← → back to the photos. With nothing focused, Tab enters the area ⌃Tab last went to (the right panels from the photos); it no longer follows the window's own Tab order, which hopped between the Presets and Library search fields. Lightroom's Tab (hide side panels) is not used.
- **Areas:** ⌃Tab / ⌃⇧Tab move between the left column, the right panels and the photos (where ← → change photo; outlined on the Filmstrip when it is showing, else on the photo, since that is where the arrows act; Rosh, Nov 9, 2026), returning to the control last used there; an accent ring with a soft glow eases in around the area, holds about 0.65 s and fades (no motion with Reduce Motion); holding ⌃ and tapping Tab walks the areas in turn. Not F6: F6 is a Windows convention, is Do Not Disturb on Mac keyboards without fn, and is Show Filmstrip in Lightroom and Atelier.
- **One mechanism:** `KeyboardFocus` in `Views/KeyboardFocus.swift` holds which control has focus, the area order and each control's key handler; the window's key handler routes arrows, Return, Space, Esc and Tab to it, so whatever shows the focus mark is always what gets the keys. It does not use SwiftUI's focus system, which only moves focus while its hosting view is first responder (the photo view takes that on a click), and so let ← → change photo while a slider showed focus. `KeyboardFocusHighlight` draws the focus mark. Tone Curve points and Color Grading wheels keep their hover-and-arrow keys.

The bars under the photo show **icons with tooltips at every width**: Before and After (Off, Side by Side, Slider) and Fit / Fill (100% and 200% stay as text), each tooltip naming the button and its key. One shared `IconSegmentedControl` (per-segment tooltips) draws them in Develop, Loupe and the HDR editor.

Help > Keyboard Shortcuts (⌘/) lists all single-key commands with their current keys plus the menu shortcuts, with a link to change keys. Help > Atelier Help (⌘?) opens the help pages (see Atelier Help).

### Settings format

Develop settings are a JSON document with a schema version, stored in the catalog and mirrored to XMP in a custom namespace. The renderer reads the same JSON, which makes settings diffable, scriptable and portable between catalogs.

**Current-edit recovery (Oct 30, 2026):** Write XMP for Selection / Write All Unsaved XMP saves current Develop settings, including masks and panel switches, alongside metadata. Develop saves (including reset, presets and pasted settings) mark XMP unsaved; Settings > Metadata automatic writing includes those saves and import settings. RAW/JPEG files with the same stem keep separate exact-filename entries in the shared sidecar. Standard metadata remains shared. The custom `atelier:DevelopRecovery` tag contains format-version-1 JSON with a `files` dictionary mapping each full filename to its schema-versioned settings JSON string. Reimport into a new catalog restores matching current settings before generating previews; recovered settings take priority over an import preset, including an explicitly neutral recovered state. Never-edited photos have no recovery entry, so metadata-only XMP writes do not suppress a future import preset. Import automatic writing targets only new photos that received recovered settings or a preset. Existing catalog assets are skipped and keep their edits. Old metadata-only sidecars import normally; supported older settings schemas take their existing defaults. Unsupported/corrupt Atelier recovery entries, including recognizable Atelier packets in damaged XML, are reported as import problems without substituting neutral edits or a preset. Unparseable foreign sidecars without a recognizable recovery marker do not block import, preserving the existing metadata-import behavior; writes still refuse to replace unreadable sidecars. Writes preserve foreign tags and sibling filename entries, and refuse to replace unreadable sidecars or unsupported/corrupt matching recovery entries. Rename a photo only with a corresponding recovery-entry update; filename matching does not recover renamed files automatically. A collision-renamed copy may retain an old filename entry from the copied sidecar; the recovered current settings are stored in the catalog and writing XMP adds the destination filename entry.

**History and snapshot recovery (AT-005a):** catalog XMP writes also save a separate `atelier:HistoryRecovery` format-version-1 JSON packet, with exact-filename entries containing the current settings JSON binding and history JSON. It retains named steps, dates, selected position, redo steps and snapshot IDs/names/dates/settings. Import validates every historical setting, position and snapshot identity; the selected step must match the current settings. Empty histories (including snapshots without edit steps) remain valid. Unsupported, damaged, orphaned or stale matching history entries fail visibly and preserve the sidecar, rather than substituting a preset or silently dropping history. An older app can read current settings but may leave stale history when it writes new edits; use the current app to maintain these backups. Settings-only callers in the current app remove their matching history entry when replacing settings, preserving sibling entries. Metadata-only writes preserve history. Settings/history save snapshots and unsaved comparisons include history-only changes. Earlier catalog records with the legacy empty `[]` history export as empty history. Existing photos need an explicit XMP write to back up earlier history. History retention is unchanged: current code retains at most 500 steps; this recovery change does not fulfill the unlimited-history requirement above.

Sidecars without history restore one current state, labeled “Recovered from XMP”. Recovery does not reconstruct virtual copies, stacks, collections or AI provenance (AT-005b/c). Subject/object masks restore selection instructions and are regenerated by Vision; exact edges can change across OS versions. Originals and rendered external/AI files still need separate backups. Settings in this custom namespace are for Atelier recovery, not Adobe-compatible Develop edits. Existing catalogs need an explicit Write XMP for Selection to back up earlier Develop edits; this change does not retroactively mark every photo unsaved.

## External editor integration

Every outside tool, whether a desktop app or an AI model, plugs in through one **Processor** contract: accept one or more ordered, typed inputs (rendered images or read-only original copies) plus parameters, and return validated image files or hand off an interactive session to a desktop app. The catalog records every source relationship independently of visual stacking. Existing single-photo Edit In and AI behavior is preserved; grouped HDR inputs are a planned extension, not an implemented capability.

### Edit In (interactive apps)

1. User picks Edit In and an app from a configurable list (Photoshop, Affinity Photo, Pixelmator Pro, GIMP, Krita, any app that opens TIFF).
2. The app renders the photo with current develop settings to the chosen format: 16-bit TIFF (default), PSD, or the original file for apps that read RAW.
3. The file is written next to the original (or to a managed edits folder for read-only volumes) and opened with that app.
4. An FSEvents watcher detects saves and refreshes the preview live.
5. The edited file is cataloged as a version, stacked on top, inheriting metadata and keywords.

Per-app settings: file format, bit depth, color space, resolution, filename template, and whether to apply develop settings first.

As built (Oct 26, 2026):
- Photo > Edit In (the first app is ⌥⌘E) and right-click > Edit In list the installed editors Atelier knows (Photoshop, Affinity Photo, Pixelmator Pro, Photomator, GIMP, Krita), then Other Application…, which adds the chosen app to the list.
- Settings > Edit In edits the list: add any app, rename, remove, Find Installed Editors, and per app the file (16-bit TIFF or JPEG), color space (sRGB, Display P3, Adobe RGB or ProPhoto RGB, the default) and Include develop adjustments.
- The copy is named `<name>-Edit.tif` next to the original, or in Pictures/Atelier/Edits when that folder is read-only. It is cataloged stacked on the original: it sorts right after it, joins the same import entries and collections, and inherits rating, label, title, caption and keywords. Grid badges show "▤ n" on the original and "◪ Edit" on the copy.
- Saves in the editor are picked up by watching the folder (and on switching back to Atelier, and when the photo is shown after a relaunch): the file's size and dimensions are re-read and the previews rebuilt. Edit In on a photo that already is an edit opens it as it is (Lightroom's Edit Original).
- PSD and RAW pass-through wait for v1.

Project-owned verified source copies are the MVP default, created on first Save rather than on opening an original. Closing before any Save leaves no project/source copy. ### Processor plugins (headless tools)


For tools without a UI (command-line denoisers, scripts, other AI servers):

- A plugin is a folder with a `manifest.json` (name, version, inputs, parameters schema, output format) and an executable or an HTTP endpoint.
- The app runs it as a sandboxed child process (stdin/stdout JSON) or calls the endpoint, passing file paths and parameters.
- Parameters render as an auto-generated form from the JSON schema.
- Progress, cancel and error reporting follow one protocol for every plugin.
- Built-in AI backends (next section) implement the same contract, so a recipe can mix a Photoshop action, a CLI tool and an AI model.

## AI processing

AI runs locally through swappable backends behind the Processor contract. The app owns the UX (masks, prompts, references, versions); backends only turn inputs into pixels.

### Requirements

- **Model registry.** Each model entry stores name, version, backend, file paths, size, memory need, and license with an allowed-use flag (commercial, personal, research). The registry is a JSON file the user can edit.
- **License gate.** Exports tagged for the website or shop block versions produced by a non-commercial model and show which model made them. Qwen-Image-2.1, Fibo 2.0 and FLUX.2 [klein] 9B are allowed for experiments only.
- **Recipes.** A recipe is an ordered list of Processor steps with saved parameters (for example, denoise, then remove distractions, then upscale 2x). Recipes run on one photo or a batch queue.
- **Masked compositing.** Generative models regenerate the whole frame. The app composites only the masked region back onto the original, with feathering, so untouched pixels stay identical. Essential for artwork photos.
- **Inputs.** Prompt, negative prompt, mask, up to 4 reference images picked from the catalog, seed, steps, strength.
- **Provenance.** Every AI version records model, version, recipe, seed and prompt in the catalog and in XMP, so any result can be reproduced or audited.
- **Queue.** One GPU job at a time, background priority, cancel, retry, and an estimate per job. The UI stays responsive while a job runs.
- **As built (Oct 26, 2026).** The AI tool in Develop (the wand button in the tool strip, or Photo > Remove Object…, Replace Background…, Upscale…) shows the ComfyUI connection, the three recipes, and Generate with progress and Cancel.
  - Remove Object: paint over what should go (Brush Size, [ and ] to resize, Paint or Erase, Clear) and optionally say what it is. Only the area around the strokes is sent, at the generation size, so detail stays high; the result is blended back with a grown, feathered mask.
  - Replace Background: Vision finds the subject on the photo (the background to regenerate is tinted), and the prompt describes the new background. The subject's pixels are kept.
  - Upscale: 2× or 4× with a 4× upscale model.
  - **Progress percentage (Oct 28, 2026).** While ComfyUI generates, the AI panel and the overlay on the photo show "Generating… N s" with a bar and an approximate percentage under it. Atelier follows the prompt on ComfyUI's websocket (`/ws?clientId=`): each node counts by how long it usually takes, the running sampler or tiled upscale by its own steps, other nodes by their time so far (never past 90% of their usual time), and nodes ComfyUI skips as cached (models already loaded) drop out. Usual times start as guesses by node kind and are then learned from each finished run, per recipe and generation size, so the percentage matches this Mac after the first run. It never goes back and only shows 100% when ComfyUI says it's done. Without a websocket connection only the seconds show.
  - Results are 16-bit TIFFs named `<name>-AI <Recipe>.tif` next to the original, stacked on it with a "✦ AI" badge, and record recipe, workflow, edit model, the models used with their licenses and allowed use, prompt, seed, generation size, region and server as provenance. The original never changes.
  - Settings > AI: server address (default http://127.0.0.1:8188; the ComfyUI desktop app uses :8000) with Connect, the edit model and upscale model picked from what the server has, generation size (768, 1024 or 1536 px), and Show Workflows Folder. A workflow saved in API format as remove-object.json, replace-background.json or upscale.json replaces the built-in one, with inputs found by node title (Atelier Image, Atelier Mask, Atelier Prompt, Atelier Sampler, Atelier Edit Model, Atelier Upscale Model, Atelier Output Scale, Atelier Output).
  - **Edit model (Oct 28, 2026).** Remove Object and Replace Background run Qwen-Image-Edit-2511 (Apache 2.0) in ComfyUI: the Q6_K GGUF (16.9 GB, via the ComfyUI-GGUF custom node, sized for 48 GB Macs), the Qwen2.5-VL 7B text encoder (bf16; fp8 files don't run on Apple GPUs), the Qwen-Image VAE and the 4-step Lightning LoRA (all Apache 2.0), sampled in 4 steps at CFG 1. The reference latent is encoded at the generation size (ReferenceLatent), not rescaled to 1 MP by Qwen's encoder, so 768 px is about twice as fast as 1024 px (1024 px took about 3 min on an M4 Pro). The photo is the edit reference and the mask limits which latent area is regenerated (SetLatentNoiseMask). For Remove Object the model's reference shows the painted area filled solid red (with the photo as is, the first test on Oct 28 redrew the tree it was meant to remove), and the instruction is "Remove the red area and fill it with the surrounding background…", naming what was there when the optional "What it is" field is filled; Replace Background wraps the description as "Replace the background with …. Keep the subject exactly as it is." Each built-in recipe lists its models and licenses, so the license gate can check a result; a custom workflow or a different edit model is recorded as license unknown.
  - Still to come: model registry, license gate on export, reference images, batch queue.
- **Agent access (later).** An MCP server exposes search, develop and recipe tools so an AI agent can drive the catalog.

## Architecture and tech stack

A native Swift app with three layers; every external tool and AI model sits behind the Processor host, so adding a backend never touches the catalog or UI.

> Diagram (see live doc): App UI (Library, Develop, AI panel, Export) -> Core services (Catalog service, Render engine, Job queue, Processor host) -> Storage (catalog and previews on local SSD; originals on local drives and megham NAS) and Processors (external apps, plugins, AI backends).

AI backends and plugins run as separate processes, so a crash or memory spike in a model cannot take down the app.

| Layer | Choice | Why |
| --- | --- | --- |
| UI | SwiftUI, AppKit for the grid and loupe (NSCollectionView, Metal-backed views) | SwiftUI alone struggles with 100k-item grids |
| Catalog | SQLite via GRDB, WAL mode | Fast, embeddable, observable queries for live UI |
| RAW and render | Core Image (CIRAWFilter) on Metal, custom Metal kernels for masks and curves | Apple's RAW engine, GPU throughout |
| Masks | Vision (subject, person), Core ML (sky, SAM 2 port) | On-device, no Python for common masks |
| Metadata | ImageIO for EXIF and XMP; Exiv2 for formats ImageIO misses | Broad read and write coverage |
| File watching | FSEvents; security-scoped bookmarks | Sandbox-safe access to drives and NAS |
| AI bridge | URLSession + WebSocket client for ComfyUI; XPC or child process for MLX workers | Process isolation |
| Plugins | JSON manifest + child process (stdin/stdout JSON) or HTTP | Language-agnostic |
| Concurrency | Swift structured concurrency, actors for the catalog and job queue | Safe background work |

## Data model and storage

The catalog is one SQLite database (WAL mode) in a `.atelier` package on the local SSD, never on the NAS. Previews live beside it in a sharded cache folder.

| Entity | Key fields | Notes |
| --- | --- | --- |
| Volume | id, uuid, name, kind (local, NAS), last seen, online | Matched by volume UUID, not mount path |
| Folder | id, volume id, relative path | Mirrors disk |
| Asset | id, folder id, filename, content hash, perceptual hash, capture time, camera, lens, dimensions | One per original file |
| Version | id, asset id, kind (develop, virtual copy, external edit, AI), parent version id, file path (if rendered), created at | Forms the stack |
| DevelopSettings | version id, schema version, JSON, history JSON | Parameters only, no pixels |
| Mask | id, version id, kind, parameters or bitmap path | AI masks cached as 8-bit PNG |
| Metadata | asset id, rating, flag, label, title, caption, GPS | Synced to XMP |
| Keyword / Collection | id, name, parent id; join tables to assets | Hierarchical |
| ImportGroup | id, name, created at; join table to assets | One per import entry; deleting it keeps the photos |
| Processor | id, kind (app, plugin, backend), versioned capabilities/configuration; ordered typed inputs and source-linked results or interactive handoff | One contract for external apps, plugins and AI; grouped HDR extension planned |
| Model | id, processor id, name, version, license, allowed use, paths | The model registry |
| Job | id, version id, recipe JSON, model id, seed, status, timings, error | Also the provenance record |

Backups: the catalog is snapshotted on quit (keep the last 10) and can be copied to the NAS. XMP sidecars are the recovery path if the catalog is lost.

## Non-functional requirements

Targets assume an M4 Mac and a catalog of 100k photos. They are starting targets to validate in the MVP, not measured figures.

| Area | Requirement |
| --- | --- |
| Grid performance | Scroll 100k thumbnails without dropped frames; filter results in under 200 ms; opening a folder or import shows cached thumbnails immediately, and missing ones load asynchronously, on-screen first |
| Import | Catalog and thumbnail 1,000 RAW files in under 3 minutes from local SSD; NAS imports never block the UI |
| Develop | Slider changes reflect in under 50 ms on the proxy; loupe opens in under 300 ms from preview cache |
| AI jobs | Run in a separate process; a crash or out-of-memory never takes down the app or corrupts the catalog |
| Data safety | Originals are read-only; catalog writes are transactional; hash-verified copies on import |
| Privacy | No network calls except NAS, user-configured backends and update checks; no telemetry |
| Sandboxing | App Sandbox with security-scoped bookmarks for each volume and folder the user grants |
| Accessibility | Full keyboard workflow for culling; VoiceOver labels on all controls |
| Compatibility | macOS 15 and later. Apple Silicon is the main target: performance targets above are measured there. Intel Macs that run macOS 15 are supported through x86_64 and universal Release builds (decided Nov 6, 2026; see Compatibility: Apple Silicon and Intel below) |

### Compatibility: Apple Silicon and Intel

Decided Nov 6, 2026 (Rosh): Atelier builds for both Apple Silicon (arm64) and Intel (x86_64), as separate apps or one universal app. Before this it was Apple Silicon only.

- **Builds.** Release builds come from `python3 Scripts/build_macos_app.py --arch arm64|x86_64|universal|all`, or from Xcode with the Release build configuration and the Any Mac (Apple Silicon, Intel) destination. Local, ad-hoc-signed builds; nothing is notarized or distributed yet.
- **Same features, same catalog.** The catalog, previews, presets and XMP are identical on both; a catalog moves between Macs unchanged.
- **Works on Intel, slower:** Core Image rendering with the runtime Metal kernels (every Mac that runs macOS 15 has a Metal GPU), Vision masks (Select Subject), culling feature prints and the splash saliency crop. No Neural Engine, so Vision tasks run on the GPU or CPU.
- **Apple Silicon in practice:** the ComfyUI backend. ComfyUI is installed separately and current PyTorch has no Intel Mac builds, so the AI tools may simply find no server on an Intel Mac; Atelier already handles an unreachable server.
- **Apple Silicon only:** the MLX backend (not built yet). When it is added it must be compiled out or hidden on Intel (`#if arch(arm64)` or a runtime check), not shown and then fail. The same goes for any later Core ML model that needs the Neural Engine or `Float16`.
- As of Nov 6, 2026 no app code is architecture-specific (no `Float16`, MLX, `#if arch` or direct Metal device code), so nothing needed guarding for the first Intel build.

## Milestones and roadmap

Five phases, each closed by a gate you can test on your own photos. No dates yet; each phase starts only when the previous gate passes. Exception (decided Oct 26, 2026): Phase 1 is built before Phase 0, and the ComfyUI round-trip moves to Phase 3.

1. **Phase 0: Spike.** RAW decode on Metal, ComfyUI round-trip, SQLite catalog prototype.
   - Gate 1: a RAW renders, goes through ComfyUI and returns as a version.
2. **Phase 1: Catalog MVP.** Referenced and copied import, import entries, grid and loupe, ratings, keywords, collections, XMP sidecars.
   - Gate 2: a real shoot (a few hundred photos) from the SSD and one from the NAS cataloged without errors, with folders opening fast. Automated scale tests in CI cover larger catalogs (filtering 20k photos, importing 300 with previews).
3. **Phase 2: Develop basics and Edit In.** Basic panel, crop, history, presets, export presets, Photoshop and Affinity round-trip.
   - Gate 3: one full shoot culled, edited and exported without Lightroom.
4. **Phase 3: AI MVP.** ComfyUI recipes, masked compositing, model registry, license gate on export.
   - Gate 4: a website image with an AI edit passes the license gate.
5. **Phase 4: v1.** Curves, HSL, AI masks, Core ML and MLX backends, plugins, batch queue, offline NAS mode.

Phase 3 depends only on the catalog and Processor host, so it can start in parallel with Phase 2 if AI is the higher priority.

## Risks and open questions

The largest risk is scope: a full develop module at Lightroom parity is years of work for a team, so it is phased and the external-editor path covers gaps meanwhile.

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Develop-module scope | MVP slips by months | Ship basic tools first; route advanced edits through Edit In until parity |
| RAW quality vs Adobe | Colors look different from Lightroom | Use Apple's RAW engine plus custom camera profiles; compare on a reference set |
| AI memory on Mac | Large models swap or fail | Quantized GGUF, one job at a time, memory check before a job starts |
| Model license drift | A model's license changes or is misread | Registry stores license per version; gate exports; review on every model update |
| NAS latency | Slow browsing and imports | Previews cached locally; background import; offline mode |
| Sandbox limits | Launching external apps or reading NAS paths fails | Security-scoped bookmarks; test early; fall back to a non-sandboxed build for personal use |
